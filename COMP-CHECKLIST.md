# Component Checklist

As you build your component, you can use this checklist to make sure you're following the correct procedures. Be sure to communicate with each other about the state of various aspects of your component.

## 1. Purpose and Role
 - This component has a clear purpose in the app.
 - This component belongs to the correct feature area.
 - This component supports the user flow, not just the layout.
 - This component has a clear name that matches what it does.
## 2. Inputs and Outputs
 - I know what data this component receives.
 - I know what this component displays or returns.
 - Props are clearly named and make sense.
 - The component does not take unnecessary props.
 - The component uses controlled, predictable data.
## 3. Content and UI
 - All labels, headings, and button text are clear.
 - The component shows the most important information first.
 - The layout supports scanning and readability.
 - The design uses contrast, alignment, repetition, and proximity.
 - Font sizes, spacing, and colour choices are consistent with the app.
## 4. States
 - I included a default state.
 - I included a loading state if needed.
 - I included an empty state if needed.
 - I included an error state if needed.
 - I tested the component with realistic content lengths.
## 5. Accessibility
 - The component uses semantic HTML where possible.
 - Form controls have labels.
 - Images/icons have appropriate alt text or are hidden from screen readers when decorative.
 - Colour is not the only way information is communicated.
 - Keyboard users can access and use this component.
 - Focus states are visible.
## 6. Responsive Design
 - The component works on mobile screens.
 - The component works on tablet screens.
 - The component works on desktop screens.
 - Text does not overlap or get cut off.
 - Buttons and interactive elements remain easy to use on small screens.
## 7. System and Architecture
 - The component fits into the shared app structure.
 - The component is reusable where appropriate.
 - The component is not doing too many jobs at once.
 - Logic and presentation are organized clearly.
 - This component is easy for another team member to understand and use.
## 8. Project-Specific Checks
 - The component supports the Take the Next Step app goals.
 - The component uses the agreed shared data structure.
 - NOC-related content is displayed clearly where relevant.
 - Wage, next step, or lookforward information is easy to understand where relevant.
 - The component helps users make a decision, not just read information.
## 9. Code Quality
 - The code is clean and consistently formatted.
 - Unused code, props, and imports have been removed.
 - Class names are readable and organized.
 - The component follows React, Tailwind, and shadcn/ui conventions used by the team.
 - Another student could maintain this component without guessing.
## 10. Final Review
 - I tested this component before handoff.
 - I checked it with realistic sample data.
 - I am confident this component is ready to integrate.
 - I documented anything another team needs to know.
